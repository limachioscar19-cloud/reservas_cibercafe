PORTAFOLIO DE AVANCES

Historia de desarrollo · NEXUS GAMING LOUNGE

Este índice reúne las etapas principales del proyecto, desde su estructura inicial hasta las mejoras de modularidad, responsividad, accesibilidad y pruebas. Cada fase tiene su propio archivo HTML con una explicación y una demostración independiente.

Estado general

Las fases 01 a 17 documentan las etapas, funcionalidades y mejoras del prototipo. El proyecto utiliza almacenamiento local; no incluye conexión a Supabase.

  1. Fase 01 · Identidad y estructura inicial del proyecto

    Se establece NEXUS GAMING LOUNGE como sitio web para presentar una experiencia de entretenimiento gaming. Se organiza la página en secciones y navegación principal, con una identidad visual oscura orientada al tema gamer.

  2. Fase 02 · Catálogo de salas gaming

    Se incorpora el catálogo de salas con imágenes, descripciones, categorías y precios por hora. Las tarjetas se generan desde datos y permiten explorar las alternativas disponibles.

  3. Fase 03 · Búsqueda y filtros del catálogo

    Se añaden herramientas para localizar salas por texto y categoría. El catálogo se actualiza sin tener que escribir manualmente una tarjeta HTML por cada elemento.

  4. Fase 04 · Formulario de reservas y validaciones

    Se desarrolla el flujo de reserva con datos del cliente, selección de sala, fecha, hora y duración. Se incorporan validaciones de formato y consistencia para reducir datos incorrectos.

  5. Fase 05 · Cálculo de precios y promociones

    Se incorpora el resumen económico de la reserva, calculando el precio según la sala y la duración. El proyecto contempla una promoción de descuento para reservas de varias horas.

  6. Fase 06 · Consulta y gestión de reservas

    Se incorpora la sección para consultar las reservas guardadas en el navegador. En esta versión, la persistencia es local mediante localStorage, por lo que no representa todavía una base de datos compartida entre dispositivos.

  7. Fase 07 · Catálogo de pedidos y carrito

    Se agrega el catálogo de productos y accesorios, organizado por categorías. El usuario puede añadir artículos al pedido y revisar el contenido del carrito antes de confirmar.

  8. Fase 08 · Confirmación y envío por WhatsApp

    Se añade la confirmación de la reserva y el pedido, con generación de un mensaje que resume los datos y permite continuar la comunicación con el negocio por WhatsApp.

  9. Fase 09 · PWA, manifest y funcionamiento sin conexión

    Se configura la aplicación web progresiva mediante manifest.json y sw.js. El manifest describe nombre, iconos y modo de visualización; el service worker gestiona caché de recursos para apoyar la carga cuando no hay conexión.

  10. Fase 10 · Roles y paneles de usuario

    Se incorpora un sistema de acceso por roles para diferenciar las tareas del cliente, empleado y gerente. En la versión actual es un prototipo local; no equivale a autenticación segura ni a cuentas sincronizadas en servidor.

  11. Fase 11 · Panel de gerente y administración

    Se amplía el panel del gerente con herramientas de gestión, edición de precios, consulta de ventas estimadas, estadísticas y registro de actividad. Los datos siguen sujetos al almacenamiento local del prototipo.

  12. Fase 12 · Diseño visual e inicio de sesión

    Se mejora la presentación visual del sistema con una paleta oscura, acentos de color, tarjetas, paneles y un inicio de sesión más ordenado. La intención es mantener una apariencia coherente entre las vistas de cada rol.

  13. Fase 13 · Componentes reutilizables y encapsulamiento

    Se encapsula la tarjeta de producto como unidad reutilizable. Los datos se separan de la presentación y las clases BEM delimitan los estilos para reducir colisiones. La simulación cambia únicamente la tarjeta seleccionada.

  14. Fase 14 · Mobile-First, CSS Grid y Flexbox

    Se prioriza la vista móvil con una columna y se escala a varias columnas desde 768 px. CSS Grid organiza el catálogo; Flexbox distribuye los elementos dentro de las tarjetas. El botón de simulación permite mostrar una columna manualmente.

  15. Fase 15 · Accesibilidad web (A11Y), semántica y contraste

    Se refuerza la semántica HTML5, el texto alternativo, la relación entre etiquetas y controles, el foco visible y una simulación de alto contraste. La simulación es una evidencia didáctica, no una certificación WCAG.

  16. Fase 16 · Desarrollo ágil (MVP) y Smoke Testing

    Se considera el flujo mínimo funcional antes de agregar mejoras secundarias. El Smoke Test inspecciona el DOM y presenta un diagnóstico rápido de botones, imágenes sin alt y enlaces vacíos.

  17. Fase 17 · Auditoría semántica y Hot Module Replacement (HMR)

    Se agrega una inspección en vivo de etiquetas semánticas e imágenes sin alt. HMR se documenta como capacidad del entorno de desarrollo (por ejemplo, Vite o Webpack); no es una función que GitHub Pages ejecute al publicar el sitio.
